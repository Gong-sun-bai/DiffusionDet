## 6. 训练与评估调用链

训练入口的核心流程是：

```text
train_net.py
  -> register_project_datasets()
  -> setup()
     -> add_diffusiondet_config()
     -> add_mobilenetv4_config()
     -> add_model_ema_configs()
     -> 合并 YAML 和命令行覆盖项
  -> configure_experiment()
     -> 校验 ID/元数据/随机种子/milestones/权重
     -> 自动解析 runs/<dataset>/<ID>__<NAME>
     -> 防止覆盖并写入 experiment_manifest.json
  -> Trainer
     -> build_model()
     -> DiffusionDet
     -> BACKBONE_REGISTRY 选择 ResNet / MobileNetV4 / Swin
     -> FPN
     -> DynamicHead
  -> 训练或 COCOEvaluator 评估
```

重要行为：

- 新训练拒绝使用非空输出目录；
- `--resume` 只复用规范实验目录，并验证 `last_checkpoint` 及其目标；
- 评估必须显式指定 `model_final.pth`、`model_latest.pth` 或 `model_best.pth`，并自动写入原实验的 `evaluations/<UTC时间戳>/`；
- `setup()` 仍会把展开后的完整配置写入本次输出目录；
- 正常结束写入 `result_summary.json`，异常时把失败状态写回运行清单。

### 7.2 修改链与能支持的结论

#### `sar-000`：SAR ResNet-50 基线

- 训练日志显示起始权重来自 `detectron2://ImageNetPretrained/torchvision/R-50.pkl`；
- FPN 和 DiffusionDet 隐藏维度均为 256；
- 约 110.67M 参数，`AP=64.53`。

这是 SAR 对比中的大模型基线。

#### `sar-001`：ResNet-18 + 128 通道压缩

相对 `sar-000`：

- Backbone 从 ResNet-50 改为 ResNet-18；
- `FPN.OUT_CHANNELS` 和 `HIDDEN_DIM` 从 256 改为 128；
- 权重为空，从头训练；
- 参数量减少约 68.8%；
- AP 反而提高 2.41，达到 66.94；
- 相同 Batch 下日志迭代时间从 0.4271 降到 0.2953 秒。

在现有单次实验中，它是精度、参数量和训练开销之间最好的平衡点，也是最值得优先复评的模型。但因为 `SEED=-1`、没有重复实验，不能把 +2.41 AP 全部归因于架构变化。

#### `sar-002`：ResNet-18 + 64 通道进一步压缩

相对 `sar-001`：

- FPN/隐藏维度进一步从 128 降到 64；
- ROI box head 使用 2 个 256 维 FC；
- Batch 从 16 增到 64；
- Max iter 从 397,288 降到 99,400，目标仍约为 200 个数据遍历周期；
- 参数量再减少约 48.2%，AP 下降 5.98。

该实验有一个重要配置错误：`SOLVER.STEPS=(278102, 357559)` 大于 `MAX_ITER=99400`，训练实际没有进入计划的学习率衰减阶段，最终学习率仍为 `2.5e-5`。因此它不是与 `sar-001` 完全公平的压缩对比，状态记为 `invalid`。

#### MobileNetV4-Small

相对 ResNet-50 基线：

- 参数量减少约 93.0%；
- AP 下降 9.57；
- AP50 仍有 94.16，但 AP75 只有 57.76，说明严格 IoU 下定位精度损失更明显。

它适合把模型体量放在首位的场景，但当前结果不能证明其推理速度优于 ResNet-18，因为仓库没有端到端推理延迟、吞吐或部署端测试。

#### MobileNetV4-Medium

相对 MobileNetV4-Small：

- 参数量从 7.70M 增至 20.58M，约为 2.67 倍；
- AP 提高 2.65；
- Max iter 延长到 119,280；
- milestones 仍为 69,580 和 89,514，只相当于新 Max iter 的约 58% 和 75%，不是注释声称的 70%/90%。

它提高了精度，但仍低于两个 ResNet-18 实验。是否值得采用取决于目标设备上的真实推理测试，而不是训练 step 时间。

#### PANDA 四类别

最终分类 AP：

- `feeds`：31.66
- `Bamboo_leaves`：8.45
- `shoot`：6.70
- `Bamboo`：6.15

整体 `AP=13.24`，类别差异很大。PANDA 验证集中 562 张图里有 124 张空标注图片，且四类样本分布、目标尺寸和标签质量尚未做更深入分析。该结果只能作为当前四类别基线，不能与 SAR 单类别结果比较。

### 7.3 结果可信度与限制

当前结果可用于内部交接和选择复评优先级，建议评级为“带限制可用”：

- 六个 `metrics.json` 均为合法 JSON Lines，最终评估记录与日志一致；
- 检查点中的迭代数与配置 Max iter 一致；
- 数据集和评估集名称可从日志确认；
- COCO 标注通过基础完整性检查。

限制包括：

- 每个配置只有一次最终实验，`SEED=-1`；
- 历史配置在同一路径上多次修改，输出目录又有重命名；
- `output_1/config.yaml` 被后续失败的评估命令覆盖了 `MODEL.WEIGHTS`；
- `output_3` 学习率 milestones 无效；
- MobileNetV4-Medium 的训练计划曾延长，但 milestones 没有同步按 70%/90% 重算；
- 没有独立测试集结果、置信区间、重复种子、推理延迟或端侧部署结果；
- 训练 step 时间受 Batch、模型、数据加载和中断恢复影响，只能作粗略参考。

## 8. 结果文件的正确含义

每个输出目录通常包含：

| 文件                                      | 含义                                                             |
| ----------------------------------------- | ---------------------------------------------------------------- |
| `config.yaml`                           | 启动时展开并保存的完整配置；后续命令可能覆盖它                   |
| `log.txt`                               | 命令行、完整配置、加载权重、训练速度、评估表                     |
| `metrics.json`                          | 训练指标 JSON Lines；最后带`bbox/AP` 的记录是最终评估          |
| `model_final.pth`                       | 可恢复/评估的模型检查点，含`model`、`trainer`、`iteration` |
| `model_latest.pth`                      | 新保留策略周期性覆盖的最新可恢复检查点                           |
| `model_best.pth`                        | 新保留策略按指定验证指标覆盖的最佳检查点                         |
| `best_checkpoint.json`                  | 跨断点恢复保存最佳指标值与迭代位置                               |
| `last_checkpoint`                       | 当前最后检查点的文件名                                           |
| `inference/instances_predictions.pth`   | 每张验证图片的预测列表，不是模型权重                             |
| `inference/coco_instances_results.json` | 展平后的 COCO 检测结果                                           |
| `events.out.tfevents.*`                 | TensorBoard 事件                                                 |
| `results.png`                           | 训练期原子更新的 2×3 指标总览；历史目录可从 `metrics.json` 补画 |

`output_1/inference/instances_predictions.pth` 实际是长度 7,946 的 Python 列表；`output_1/model_final.pth` 才是带 `model` 状态字典的检查点。

新训练默认每 200 iter 更新一次 `results.png`，周期验证和训练结束后也会
强制刷新。配置入口为 `TRAINING_PLOTS.ENABLED` 和
`TRAINING_PLOTS.PERIOD`。已有结果目录使用同一渲染器补图：

```bash
python tools/generate_training_plots.py \
  runs/sar_ship/sar-001__r18-fpn128-h128-bs16-it397288-scratch
```

脚本只新增或替换 `results.png`，不会修改历史 `metrics.json`、`log.txt`、
`config.yaml`、权重和实验清单。六组历史训练都只有最终一次 bbox 评估，
所以补图中的 AP 是带数值的最终单点；只有启用周期验证的新实验才会形成
AP 曲线。当前必要总览不包含 PR、F1 和混淆矩阵，因为这些数据不在
`metrics.json` 中。

## 10. 恢复训练时的特殊处理

历史配置被标记为 `KIND=historical`，入口禁止训练和 `--resume`。已完成到 Max iter 的历史检查点也不应原地延长。

只有尚未完成的新规范实验可恢复：

```bash
python train_net.py --num-gpus 1 \
  --config-file configs/experiments/sar_ship/<running-experiment>.yaml \
  --resume
```

入口会自动解析原目录并验证 `last_checkpoint`。采用 latest/best 策略时标记应指向 `model_latest.pth`，而不是 `model_best.pth`。若要延长训练，应分配新实验 ID、重设 Max iter/milestones，并在实验日志中明确是加载旧模型还是恢复完整 optimizer/scheduler 状态。

## 12. 快速故障定位

| 现象                                           | 首先检查                                                                                |
| ---------------------------------------------- | --------------------------------------------------------------------------------------- |
| `Dataset 'sar_ship_train' is not registered` | `diffusiondet/datasets.py` 是否被入口调用、数据路径是否存在                           |
| `No module named torch/fvcore/pycocotools`   | 是否激活`Difdet`，不要用 `/usr/bin/python3`                                         |

| `--resume` 找不到检查点                      | 规范实验目录内的`last_checkpoint` 及其目标是否存在                                    |
| 评估被入口拒绝                                 | 是否显式指定了允许的模型权重文件，且没有同时传`--resume`                              |
| 原 Batch OOM                                   | 历史峰值显存高于本机 22,528 MiB，降低 Batch                                             |
