# DiffusionDet 实验日志

> 建档日期：2026-07-23
> 适用范围：SAR 船舶检测、PANDA 四类别检测及后续 DiffusionDet 消融实验
> 机器可读证据：`runs/<dataset>/<ID>__<NAME>/experiment_manifest.json`

## 1. 当前结论

- SAR 历史结果中 `sar-001` 的 `AP=66.94` 最高，但其 `SEED=-1`，只能作为方向性参考，不能充当正式可重复基线。
- `sar-002` 的 `SOLVER.STEPS` 全部大于 `MAX_ITER`，训练未发生计划中的学习率衰减，状态记为 `invalid`。
- MobileNetV4-Small 将完整检测模型压缩到约 7.70M 参数，但相对 `sar-000` 的 AP 下降 9.57；MobileNetV4-Medium 增至 20.58M 后恢复 2.65 AP，仍低于 ResNet-18。
- PANDA 是四类别任务，且含空标注图片；`panda-000` 不得与 SAR 单类别实验直接横向比较。
- `sar-005` 已完成实际配置中的 254,264 iter，最终 `AP=58.84`，比 `sar-001` 低 8.10 AP。它实际使用 Batch 25、`BASE_LR=3.5e-5` 和 256–1024 多尺度训练，不是目录名所暗示的 Batch 16 / 397,288 iter，也不是对 `sar-001` 的严格复现。
- `sar-005` 已跑完约 200 次数据遍历，末段学习率降至 `3.5e-7`，最终损失在约 2.8–2.9 波动；现有证据不支持“只是还没收敛”。首要待验证因素是其多尺度训练与 `sar-001` 固定 256 输入的差异，其次才是随机种子及 Batch/学习率轨迹。

## 2. 状态与证据规则

实验状态只使用：

- `planned`：配置与假设已登记，尚未启动；
- `running`：输出目录和运行清单已创建，训练或评估正在进行；
- `completed`：进程正常结束并写出 `result_summary.json`；
- `failed`：运行异常，错误类型和消息已写入清单；
- `invalid`：运行结束但关键设计错误使结果不能作为公平对照。

证据优先级：

1. 实际加载权重、恢复位置和运行行为以 `log.txt` 为准；
2. 指标以 `metrics.json` 最后一条含 `bbox/AP` 的记录为准；
3. 结构以输出目录内冻结的 `config.yaml` 为准；
4. 历史汇总和已知问题以 `experiment_manifest.json` 和本文档为索引；
5. 禁止修改历史 `log.txt`、`metrics.json`、`config.yaml`，禁止用新结果覆盖旧目录。

## 4. 历史实验逐项记录

### `sar-000`：SAR ResNet-50 参考

- 配置：`configs/experiments/sar_ship/sar-000.yaml`
- 结果：`runs/sar_ship/sar-000__r50-fpn256-h256-bs16-it397288-pretrain`
- 基线：无。
- 目的：建立大模型 SAR 精度参考。
- 假设：ImageNet 预训练的 ResNet-50 与 256 通道检测头可提供可靠基准。
- 修改位置：`MODEL.RESNETS`、`MODEL.FPN.OUT_CHANNELS`、`MODEL.DiffusionDet.HIDDEN_DIM`、`MODEL.WEIGHTS`。
- 结论：AP 64.53；参数量和显存明显高于 `sar-001`，当前不优先复跑。
- 限制：`SEED=-1`；后续失败评估覆盖过冻结配置的 `MODEL.WEIGHTS`，原始训练确实加载了 ImageNet 权重，以日志为准。
- 原命令：终端输出未被日志捕获，无法无损恢复；禁止在文档中伪造。

### `sar-001`：SAR ResNet-18 / 128

- 配置：`configs/experiments/sar_ship/sar-001.yaml`
- 结果：`runs/sar_ship/sar-001__r18-fpn128-h128-bs16-it397288-scratch`
- 基线：`sar-000`。
- 目的：验证较小骨干与 128 通道结构的精度/体量平衡。
- 假设：SAR 单类别任务不需要 R50/256 的容量。
- 修改位置：ResNet 深度、FPN/隐藏维度和预训练权重。
- 结论：AP 提高 2.41，参数量减少约 68.8%，是当前最值得复现的方向。
- 限制：同时改了骨干、通道和预训练方式，且 `SEED=-1`，不能把提升归因于单一因素。

### `sar-002`：SAR ResNet-18 / 64

- 配置：`configs/experiments/sar_ship/sar-002.yaml`
- 结果：`runs/sar_ship/sar-002__r18-fpn64-h64-bs64-it99400-scratch`
- 基线：`sar-001`。
- 目的：进一步压缩通道与全连接层。
- 假设：64 通道可继续减小模型并保留可用精度。
- 修改位置：FPN/隐藏维度、ROI FC、Batch 和训练长度。
- 结论：参数降至 17.88M，但 AP 下降 5.98。
- 限制：`STEPS=(278102,357559)` 大于 `MAX_ITER=99400`，无计划降学习率；多项变化耦合，状态为 `invalid`。

### `sar-003`：MobileNetV4-Small

- 配置：`configs/experiments/sar_ship/sar-003.yaml`
- 结果：`runs/sar_ship/sar-003__mnv4-small-fpn64-h64-bs64-it99400-scratch`
- 基线：`sar-000`。
- 目的：探索极小检测模型。
- 假设：MobileNetV4-Small 可显著缩小模型。
- 修改位置：`diffusiondet/mobilenetv4.py` 及 backbone/FPN/hidden 配置。
- 结论：仅 7.70M 参数；AP 54.96，AP75 损失尤其明显。
- 限制：没有推理延迟、吞吐和端侧部署数据，不能由参数量直接推断速度。

### `sar-004`：MobileNetV4-Medium

- 配置：`configs/experiments/sar_ship/sar-004.yaml`
- 结果：`runs/sar_ship/sar-004__mnv4-medium-fpn96-h96-bs50-it119280-scratch`
- 基线：`sar-003`。
- 目的：用更大移动骨干换取精度。
- 假设：Medium 能在仍较小的模型体量下明显恢复 AP。
- 修改位置：MobileNetV4 尺寸、FPN/hidden、Batch 和训练长度。
- 结论：比 Small 增加 2.65 AP，但参数约为 2.67 倍，仍低于 R18。
- 限制：训练延长后 milestones 没按 70%/90% 重算；多次中断恢复。

### `panda-000`：PANDA 四类别参考

- 配置：`configs/experiments/panda/panda-000.yaml`
- 结果：`runs/panda/panda-000__r50-fpn256-h256-bs16-it49063-pretrain`
- 基线：无。
- 目的：建立 PANDA 四类别初始结果。
- 假设：R50 DiffusionDet 能建立可继续优化的四类基准。

## 5. 新基线与后续消融队列

### `sar-005`：固定种子正式基线

- 状态：`completed`
- 配置：`configs/experiments/sar_ship/sar-005.yaml`
- 结果：`runs/sar_ship/sar-005__r18-fpn128-h128-bs16-it397288-scratch-seed40244023`
- 基线：无；结构参考历史 `sar-001`。
- 实际设置：R18、FPN/HIDDEN 128、scratch、`SEED=40244023`、Batch 25、`BASE_LR=3.5e-5`、254,264 iter、milestones 177,985/228,838、训练输入 256–1024 多尺度、测试短边 256 / 长边上限 1024。
- 原定目的：建立后续所有 SAR 消融共享的可重复起点。
- 假设：固定种子后应复现历史 R18-128 的方向性优势。
- 结果：`AP=58.8383`、`AP50=95.6121`、`AP75=65.4480`、`APs=52.7774`、`APm=66.0107`、`APl=77.3167`；参数量 34,462,942；峰值显存 19,403 MB；训练时长 5天17:28:55。
- 与 `sar-001` 的差异：AP -8.10、AP50 -1.22、AP75 -14.90、APs -9.45、APm -7.69、APl -3.27。差距主要集中在高 IoU 和小目标。
- 收敛判断：训练正常到达 `MAX_ITER=254264`，约处理 6,356,600 张训练样本，等价于约 200 次完整数据遍历；末段学习率为 `3.5e-7`，最后几次记录的 `total_loss` 约 2.80–2.88，没有仍在快速下降的证据。因此不建议直接延长本次训练来解释 8.10 AP 差距。
- 结论：该结果可以作为“固定种子 + Batch 25 + 多尺度”的独立基线，但不能称为 `sar-001` 的严格复现。最显著的实验差异是 `sar-001` 使用固定 256 输入，而本次使用 256–1024 随机多尺度；Batch、学习率和更新次数也不同。
- 命名限制：目录与 `EXPERIMENT.NAME` 中的 `bs16-it397288` 已与实际冻结配置不一致。历史运行目录不改名、不覆盖；后续以冻结 `config.yaml` 和本条记录为准。
- 详细分析：`docs/reports/sar-005-vs-sar-001/report.html`

### `sar-006`：proposal 数示例

- 状态：`planned`，暂缓。`sar-005` 已证明不是可靠的 `sar-001` 固定 256 复现，proposal 消融应等待 `sar-008` 结果后再决定是否重设基线。
- 配置：`configs/experiments/sar_ship/sar-006-proposals300.yaml`
- 基线：`sar-005`
- 唯一变量：`MODEL.DiffusionDet.NUM_PROPOSALS: 500 -> 300`
- 目的：测量 proposal 数对精度和计算开销的影响。

### `sar-007`：RTX 2080 Ti 训练冒烟

- 状态：`completed`
- 类型：`smoke`，不参与精度比较。
- 配置：`configs/experiments/sar_ship/sar-007-smoke.yaml`
- 输出：`runs/sar_ship/sar-007__r18-fpn128-h128-bs16-it20-smoke-seed40244023`
- 基线结构：`sar-005`
- 目的：验证 PyTorch/Detectron2 ABI、SAR 数据、R18/FPN128 模型、Batch 16 反向传播和检查点链路。
- 结果：20 iter 完成；平均 1.2456 秒/iter；训练主体 23 秒；端到端 32.63 秒；峰值显存 12,626 MB。
- 产物：`model_final.pth`、`last_checkpoint`、指标、日志、运行清单和结果摘要齐全；清单状态为 `completed`。
- 指标：iter 19 的 `total_loss=25.35935`，全部损失有限；未运行验证集，不记录 AP。
- 结论：当前 RTX 2080 Ti 可用正式基线结构和 Batch 16 启动训练；短运行峰值不等于完整训练最坏情况。
- 复现记录：`docs/RTX2080Ti基线复现记录.md`

### `sar-008`：固定 256 输入复现

- 状态：`planned`
- 配置：`configs/experiments/sar_ship/sar-008-fixed256.yaml`
- 输出：`runs/sar_ship/sar-008__r18-fpn128-h128-bs25-it254264-fixed256-seed40244023`
- 基线：`sar-005`
- 研究变量：将训练输入从 256–1024 多尺度改为固定 256，并将测试长边上限同步设为 256，以恢复 `sar-001` 的输入口径。
- 保持不变：沿用 `sar-005` 的 `SEED=40244023`、Batch 25、`BASE_LR=3.5e-5`、`MAX_ITER=254264`、`WARMUP_ITERS=1000` 和 milestones 177,985/228,838。
- 边界：按本次需求保留了 `sar-005` 的 Batch 和步数，因此它能隔离输入尺度差异，但仍不是“除随机种子外完全等同 `sar-001`”的严格复现。
- 权重策略：每 2,000 iter 覆盖写入 `model_latest.pth`；每 5,000 iter 运行验证，以最高 `bbox/AP` 覆盖 `model_best.pth`。`best_checkpoint.json` 持久化最佳分数，`last_checkpoint` 始终回指 latest，保证中断恢复不会误从 best 继续。
- 训练命令：

```bash
python train_net.py --num-gpus 1 \
  --config-file configs/experiments/sar_ship/sar-008-fixed256.yaml
```

- 恢复命令：

```bash
python train_net.py --num-gpus 1 \
  --config-file configs/experiments/sar_ship/sar-008-fixed256.yaml \
  --resume
```

推荐顺序：

1. `sar-008`：固定 256 输入，判断 `sar-005` 与 `sar-001` 的主要差距来源；
2. 根据 `sar-008` 结果确定新的消融基线；
3. 通道宽度：只改 FPN/HIDDEN 这一兼容性耦合因素；
4. backbone：固定检测头宽度和训练策略；
5. proposal 数；
6. `MODEL.DiffusionDet.SAMPLE_STEP`；
7. 输入尺度或裁剪策略，每次只选一个概念因素；
8. 分类、L1、GIoU 等损失权重。

## 6. 新实验登记规范

实验目录由入口自动生成：

```text
runs/<EXPERIMENT.DATASET>/<EXPERIMENT.ID>__<EXPERIMENT.NAME>/
```

要求：

- ID 格式为 `<数据集短名>-<三位序号>`；SAR 的 `000–008` 已占用。
- `EXPERIMENT.KIND` 可为 `historical`、`baseline`、`ablation` 或 `smoke`；`smoke` 只验证运行链路，不得报告为精度结果。
- NAME 只使用小写字母、数字和连字符，不包含 AP 或结论。
- 非历史实验必须固定 `SEED`，默认 `40244023`。
- `ablation` 必须填写 `BASELINE`、`PURPOSE`、`HYPOTHESIS`、`CHANGES`。
- `CHANGES` 每项使用 `配置键: 旧值 -> 新值`。
- 一次实验只验证一个假设；结构兼容所必需的耦合参数可一起调整，但要声明为一个概念因素。
- 新训练拒绝非空目标目录；只有 `--resume` 可复用目录，且 `last_checkpoint` 必须有效。
- 评估必须从命令行显式传入 `model_final.pth`、`model_latest.pth` 或 `model_best.pth`；`instances_predictions.pth` 永远不是权重。
- 评估结果自动写入原实验的 `evaluations/<UTC时间戳>/`，不得覆盖历史 `inference/`。
- 新权重保留策略由 `SOLVER.CHECKPOINT_RETENTION` 控制；设为 `latest` 时只覆盖一个 `model_latest.pth`。启用 `TEST.BEST_CHECKPOINT` 时必须设置正数 `TEST.EVAL_PERIOD` 和非空验证集。

历史 `sar-001` 的参考口径是 Batch 16、`BASE_LR=2.5e-5`、`MAX_ITER=397288`；已完成 `sar-005` 的实际口径是 Batch 25、`BASE_LR=3.5e-5`、`MAX_ITER=254264`。若仅因硬件容量改变 Batch，默认线性缩放学习率，按 Batch 反比缩放 `MAX_ITER` 和 `WARMUP_ITERS`，并将 milestones 设为新 `MAX_ITER` 的 70%/90%。这类适配也必须使用新实验 ID，并完整登记所有联动参数。AMP、输入尺度和模型结构变化均是独立实验因素。具体公式见 `docs/RTX2080Ti基线复现记录.md`。

历史模型复评示例：

```bash
python train_net.py --num-gpus 1 \
  --config-file configs/experiments/sar_ship/sar-001.yaml \
  --eval-only \
  MODEL.WEIGHTS runs/sar_ship/sar-001__r18-fpn128-h128-bs16-it397288-scratch/model_final.pth
```
