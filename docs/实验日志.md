## 实验目标

在可部署模型参数量严格小于 10M 的前提下，使 SAR 验证集 COCO `bbox/AP >= 61`，并通过完整训练和更换随机种子的复现实验确认稳定性。

## 2. 对比消融实验

### 2.1 改进目的

改进目标是把参数严格压到 10M 以下，同时把 AP 提高到至少 61，并尽量保持方案可迁移到一般目标检测任务，而不是针对 SAR 船舶尺寸、形状或数据分布编写规则。

参数审计发现，小模型的主要瓶颈不是约 1M 的 MobileNetV4-Small backbone，而是六套互不共享的 DiffusionDet 动态检测头。因此实验路线不是继续盲目缩小 backbone，而是：

- 先修正并诊断多步采样和逐 head 输出，确认哪些计算真正有价值；
- 共享六级迭代头，释放参数预算；
- 把释放的预算重新分配给 FPN/HIDDEN 宽度，以改善严格 IoU 下的定位；
- 接入标准 timm 轻量 backbone，验证标准结构和 ImageNet 预训练；
- 以 sar-006 为冻结教师，对最强学生做相同 noisy boxes、相同 timestep 的查询一致蒸馏；
- 用 exact 200/5k/20k/50k 分层筛选控制总耗时，筛选结束后才决定正式全量实验。

### 2.2 工程改动

- `diffusiondet/config.py`、`diffusiondet/detector.py`：配置化 `DDIM_ETA`、box renewal 和 ensemble 行为，保存最终采样步输出，修正多图 renewal/ensemble 路径，并加入逐 head 评估入口。
- `diffusiondet/head.py`：新增 `none`、`full`、`heavy` 三种 head sharing 模式；`full` 复用完整 `RCNNHead`，`heavy` 只共享最重的 DynamicConv 和 FFN。
- `diffusiondet/timm_backbone.py`：新增通用 `timm features_only` backbone 适配器，校验四级特征的 stride 为 4/8/16/32，并接入 FPN。
- `diffusiondet/detector.py`、`diffusiondet/util/box_ops.py`：新增冻结教师的查询一致分类、L1 和 aligned GIoU 蒸馏损失；教师不写入学生部署 state dict。
- `train_net.py`、`experiment_manager.py`：新增 `--run-until-iter`、exact-rung 评估、暂停/晋级/淘汰状态、配置 hash 和更密集的筛选 checkpoint，使同一完整 schedule 可以安全暂停和续跑。
- `tools/run_under10m_screening.py`、`tools/run_under10m_remaining_screening.py`：实现串行分层队列、全局锁、配置漂移保护、GPU 预检、自动晋级、蒸馏资源/指标/两周 ETA 门槛和最终报告生成。

这些改动的共同目的，是让短程筛选保持完整训练 schedule 的早期轨迹，同时避免把人工暂停误写成完成、失败或另一套实验。

### 2.4 结论

1. **10M 以下的完整训练目标已经达到。** `sar-015` 和 `sar-016` 的最佳 AP 分别为 67.8786 和 67.2254，均明显超过 61；但两者都使用种子 `40244023`，仍需更换随机种子复核稳定性。
2. **六级细化应保留，参数应通过共享而不是删 stage 来压缩。** 历史独立头逐 head 评估中，第 4 级相对第 6 级低约 3.02 AP、5.96 AP75；完全共享六级头则把 H64 模型从 7.61M 降到 2.28M，20k 只下降约 1.50 AP。
3. **把共享节省的预算回投到 H128 有效。** `sar-009` 相对 H64 共享的 `sar-008` 在 20k 提高约 2.32 AP，同时仍只有 5.64M 参数。
4. **`heavy` 部分共享没有体现性价比。** `sar-010` 比完全共享 H128 的 `sar-009` 多约 1.33M 参数，20k AP 反而低约 0.35。
5. **标准 backbone 和 ImageNet 预训练是主要有效因素。** 标准 MobileNetV4-Conv-Small 的预训练版本 `sar-012` 相对 scratch 的 `sar-011`，20k 提高 8.28 AP，50k 仍提高 5.32 AP。
6. **RepViT-M0.9 是精度优先选择。** 正式最佳结果 `sar-015` 比 `sar-016` 高 0.65 AP 和 1.41 AP75；代价是参数从 6.04M 增至 9.44M，最终验证的纯推理时间约从 0.0216 增至 0.0267 秒/图。
7. **当前查询一致蒸馏方案应停止。** `sar-014` 在 20k 和 50k 分别比无蒸馏学生低 0.48 AP 和 1.62 AP，差距随训练继续扩大。
8. **多步采样不是当前主线。** 现有权重复评中，多步采样只带来约 0～0.4 AP 波动，却显著增加 head forward 次数；1-step 仍是当前精度与延迟折中。
9. **两个 finalist 均成为有效正式方案。** `sar-015` 相对 `sar-006` 以约 72.61% 的参数降幅取得 `+0.11 AP`；`sar-016` 以约 82.48% 的参数降幅仅损失 `0.55 AP`，精度、体量和验证速度的取舍清晰。

## 5. 复现、训练与评估指令

普通训练命令具有幂等行为：当 `runs/<DATASET>/<ID>__<NAME>/` 已经非空且未传入 `--resume` 时，入口会打印该目录的绝对路径并以成功状态退出，不构建模型、不加载数据，也不改写原产物。全新 clone 中没有该目录时，同一命令才会开始训练；未完成实验必须显式使用 `--resume`。

### 5.1 全新 clone 的准备

代码仓库不包含被 Git 忽略的 SAR 数据集、`runs/` 和编译生成的 `_C*.so`。云端机器需要先准备 NVIDIA 驱动、Conda、至少 20 GiB GPU 显存、至少 30 GiB 可用磁盘和可访问 `timm` ImageNet 预训练权重的网络，再执行：

```bash
git clone https://github.com/Gong-sun-bai/DiffusionDet.git
cd DiffusionDet
PYTHONNOUSERSITE=1 conda env create -f environment.yml
conda env config vars set PYTHONNOUSERSITE=1 -n Difdet
conda activate Difdet
python tools/build_detectron2_extension.py build_ext --inplace
```

从独立存储把原始数据复制为仓库根目录下的 `SAR_COCO_ship/`。`/path/to/SAR_COCO_ship/` 必须替换为云端实际数据源；目录至少包含 `annotations/`、`train2017/` 和 `val2017/`：

```bash
cp -a /path/to/SAR_COCO_ship ./SAR_COCO_ship
```

### 6.2 历史配置校对方法

`sar-000`～`sar-004` 的证据优先级如下：

1. 首次训练 `log.txt` 的完整配置和实际加载行为；
2. 恢复训练日志与运行目录冻结 `config.yaml` 交叉验证；
3. `metrics.json` 最后一条含 `bbox/AP` 的记录用于最终指标；
4. 运行清单与本文档用于汇总限制和迁移关系。

五份配置不含 `_BASE_` 或 `OUTPUT_DIR`，显式记录模型、数据集、固定 256 输入、裁剪、优化器、Batch、学习率、迭代、milestones、测试与随机种子。`sar-000` 使用首次训练日志中的 ImageNet 权重地址，不采用被失败评估覆盖的冻结权重字段。历史设计缺陷只记录，不追溯修正。

固定 256 配置的含义是：数据映射阶段将图像按 Detectron2 的 resize 规则缩放到固定短边/受限长边，并在启用裁剪时执行相应裁剪。它不筛选数据集，也不是“只训练原本为 256×256 的图片”。本地 SAR 原图恰好均为 256×256，但这与配置语义是两件事。

### 6.3 实验规范

- 正式 ID：`<dataset>-NNN`；测试 ID：`<dataset>-test-NNN`。
- `sar-000`～`sar-016` 已被历史结果、筛选结果或独立正式配置占用；下一未占用正式编号为 `sar-017`，下一测试编号为 `sar-test-002`。
- NAME 只包含小写字母、数字和单连字符分隔的词，不包含 AP 或结论。
- 所有训练和 `--resume` 必须固定非负 `SEED`，默认 `40244023`，且每个 `SOLVER.STEPS` 必须小于 `SOLVER.MAX_ITER`；显式评估旧配置时不执行这两项训练有效性检查。
- `EXPERIMENT.DESCRIPTION` 是不参与运行逻辑的可选自由文本，建议概括对照实验、主要改动、目的和重要限制；一次只验证一个概念因素。
- 普通训练发现规范目标目录已非空时打印绝对路径并成功退出，不改写历史结果；只有显式 `--resume` 才继续未完成实验。评估写入 `evaluations/<UTC时间戳>/`，不得覆盖历史 `inference/`。
- `SOLVER.CHECKPOINT_RETENTION=latest` 周期覆盖 `model_latest.pth`；启用最佳检查点时用验证指标覆盖 `model_best.pth`，但 `last_checkpoint` 必须继续指向 latest。
- 当前优先级：从 `sar-017` 开始新建不同固定种子的复现配置，优先复现 `sar-015`，再按资源决定是否复现 `sar-016`。完成跨种子确认后，再根据精度或体量侧重点选择正式基线；需要继续优化时依次开展 proposal 数、sample step、输入尺度/裁剪和损失权重消融。

### 6.7 2026-09-11：五类雷达时频仿真数据生成工具

- 状态：生成脚本、配置、测试和说明文档已完成；仅运行独立预览及临时小规模测试，未生成正式 99,000 张数据、未进行模型训练。
- 入口：`dataser_process/generate_lpi_dataset.py`；配置 `dataser_process/configs/lpi5_v1.yaml`；详细算法、字段及一键命令见 [雷达信号仿真数据集说明](../dataser_process/雷达信号仿真数据集说明.md)。
- 数据设计：LFM、NLFM、BPSK、BFSK、Frank 五类，删除 MIMO；AWGN、各分量脉内 SNR 为 −10～10 dB 共 11 档。总量 99,000，train/val/test 为 39,600/9,900/49,500，包含 10% 纯噪声；五类总框数各 47,520。
- 实现：预先划分场景与平衡类别组合，独立随机流和干净能量框跨 SNR 复用；统一 640×640 灰度 RGB 输入、同源 COCO/YOLO 标注和场景元数据；支持只读预检/校验、独立预览、排他锁、原子写入和哈希保护的续生成。
- 验证：生成器 15 项测试通过，含物理方程、SNR、STFT 方向、COCO 兼容性、单/双进程逐文件一致、预览中间数组一致及中断续生成；`Difdet` 环境下原仓库 79 项测试通过。配置、历史迁移、SAR YOLO 源数据只读检查和 `git diff --check` 通过。系统 Python 缺少 PyTorch，不能用于完整仓库测试，已改用规定的 `Difdet` 环境验证。
- 正式参数独立预览：30 个干净场景×11 档 SNR，加 10 个纯噪声窗，共 340 张；五类框总计 880。最大脉内 SNR 标定误差约 `3.55e-15 dB`，最小框宽/高为 130/13 像素；已检查干净图、含噪图及框叠加图。
- 后续评价口径：AP/AP50/AP75、类别正确且 IoU≥0.5 的目标级检测率，以及纯噪声窗虚警率 `FP_win/(FP_win+TN_win)`。背景不赋 SNR，正式测试分母为 4,950 个纯噪声窗；阈值仅用验证集选一次。
- 限制：BPSK/Frank 在低 SNR 下可能外观接近；STFT 分位框不等同于精确物理带宽。训练接入尚需五类注册、关闭现有硬编码随机翻转/裁剪、保留并验证空标注批次，以及新的五类通用评估接口。当前未修改 SAR/PANDA 模型训练逻辑，未占用新训练实验 ID。
